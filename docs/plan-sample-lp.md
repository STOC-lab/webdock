# 設計: ホームページがない店向けの「見本ページ」自動作成

作成: 2026-11-18（Opus の設計。実装は Sonnet）

## 目的

Googleマップにホームページのリンクがない店（兵庫県の健康系 約300件から開始）に電話し、
その店専用の見本ページを短いURLで見てもらう。興味を持った店に無料掲載の説明をしてOKをもらい、
その会話で集客意欲を聞いて、MEO付きWEB・MEOにつながりそうなら訪問（遠方はZoom）の約束を取る。

このPRでは「見本ページを倉庫のデータから自動で作り、短いURLで表示し、開かれたかを記録する」までを作る。

## 決まっている方針（必ず守る）

1. 店の事実（店名・住所・電話・業種）は倉庫のデータをそのまま差し込む。AIに文章や数字を作らせない。
2. 営業時間は倉庫にないので、データがあれば表、なければ「営業時間は院長様に伺って掲載します」と出す（推測で書かない）。
3. 説明文と写真は「業種グループ」ごとに人が用意したものだけを使う。効果をうたう表現は入れない（整骨院は柔道整復師法で広告できる内容が厳しく制限されている）。
4. 見本であることを必ず示す:
   - ページ最上部に「営業提案用の見本です。○○様の公式サイトではありません（株式会社エストック作成）」の帯
   - フッターにも同じ趣旨と「掲載情報はGoogleマップの掲載内容（日付）をもとにしています」
   - `<meta name="robots" content="noindex, nofollow, noarchive">` と応答ヘッダー `X-Robots-Tag: noindex, nofollow`
5. 写真には「写真はイメージです」を必ず付ける。使う写真は代表者が選ぶ（人物はストック写真のモデルに限る。院のスタッフや患者に見える使い方の説明文は付けない）。
6. 写真ファイルは git に入れない（ストック写真の再配布にあたるため。このリポジトリは公開）。管理画面からアップロードして、サーバーの data/ 以下に保存する。
7. 見本は「公開しない」扱い: 検索に出さない・一覧ページを作らない・URLは推測しにくくする。断られた見本は削除できる。

## デザイン

`docs/sample-lp-reference/make_lp2.py` が参照実装（Python。デザインと構成の正）。これを EJS のビューに移植する。
`docs/sample-lp-reference/shop_example.json` は架空の店のデータ例。

構成（上から）: 見本の帯 → ヘッダー（頭文字の丸ロゴ＋店名） → バナー型ヒーロー（hero写真を全面背景＋暗いグラデーション、「地域の業種」、店名を明朝体で大きく、金色の線、キャッチ、特徴のピル、下部に濃い緑の帯で住所・電話・営業時間の要約） → リード文・電話ボタン・アクセスボタン
→ ABOUT（説明文＋3つの特徴カード。カード上部は丸く切り抜いた写真） → CONCERNS（チェックリスト） → TREATMENTS（3つのカード。上部に写真＋アイコンのバッジ、「写真はイメージです」、「院長様に確認のうえ掲載」の注記）
→ FIRST VISIT（4ステップ） → 院内写真2枚＋「写真はイメージです」 → HOURS（営業時間の表 or 未掲載の案内） → ACCESS（住所・電話・Googleマップの埋め込みと「マップで開く」）
→ 緑の問い合わせ帯 → 紺のフッター → 画面下に固定の電話ボタン。
セクションの背景は一色にせず、生成り（#fbf7f1）・白・薄いミント（#f0fdfa）・薄い青（#eff6ff）を交互に使う（色は参照実装のCSSが正）。

業種の表示（「○○にある整骨院です」など）は、店の業種名（category_main）を使う。

## 業種グループ

`src/sampleCategories.js` に定義する。店の category_main / category にキーワードが含まれるかで、上から順に判定する。

| グループID | キーワード | 写真フォルダ | 文 |
|---|---|---|---|
| seitai | 整骨・接骨・整体・鍼灸・鍼・はり・灸・カイロ | seitai | 参照実装の「整骨院」の文（業種名は差し込み） |
| massage | マッサージ・指圧 | massage（未アップロードなら seitai を使う） | 当面は seitai と同じ文。「施術」の語はそのまま |

グループに当てはまらない店は見本を作らない（作成時にスキップして件数を報告）。

## データ

新しい移行 `sql/warehouse_migrate_013.sql`（何度実行しても安全に）:

```
stoc_master.sample_pages
  id            BIGINT PK AUTO_INCREMENT
  code          CHAR(5) UNIQUE      -- 電話で読み上げる5桁の数字（10000〜99999、ランダム、重複しない）
  shop_id       BIGINT  INDEX       -- stoc_master.shops.id
  group_id      VARCHAR(20)
  hours_json    JSON NULL           -- 院長に聞いた営業時間（管理画面で入力）。NULLなら未掲載の案内
  note          VARCHAR(500) NULL   -- 営業メモ
  status        ENUM('draft','approved','deleted') DEFAULT 'draft'
                                    -- draft=見本、approved=掲載OKをもらった、deleted=削除（表示しない）
  created_at, updated_at
  first_opened_at, last_opened_at DATETIME NULL
  open_count    INT DEFAULT 0
  batch_label   VARCHAR(100) NULL   -- どのリストで作ったか（例: 兵庫_健康系_20261118）
```

開かれた記録はボット（UAに bot/crawler/spider/preview/facebookexternalhit/Slackbot など）を除いて数える。

## 画面とURL

- 表示: `GET /s/:code`（5桁の数字のみ受け付ける）。status=deleted や存在しないコードは 404。
  店の最新データ（shops）をその場で読んで描画する。描画に失敗しても他のページに影響しないこと。
- 管理画面（倉庫の管理画面に新しいメニュー「見本ページ」）:
  1. 作成: 倉庫IDの一覧（CSVのアップロード、または貼り付け）を受け取り、まとめて作る。リストの名前（batch_label）を付ける。
     作成後、入力した CSV の列に「見本コード」「見本URL」を足した CSV をダウンロードできる（電話リストとしてそのまま使う）。
     同じ店の見本がすでにあれば作り直さず、既存のコードを使う。
  2. 一覧: コード、店名、業種、市区町村、状態、開いた回数、最後に開いた日時、batch_label で絞り込み。各行から見本を新しいタブで開ける。
  3. 編集: 営業時間（曜日ごとの入力。空欄は未掲載）、メモ、状態（見本／掲載OK／削除）。
  4. 写真: 業種グループごとに hero / room / reception（必須）と f_explain / f_counsel / f_room（特徴カードの丸）・t_back / t_stretch / t_head（施術案内カード）の計9枚をアップロード。任意の6枚が無いときは参照実装と同じく代用・アイコン表示にする（JPEG/PNG、1枚5MBまで、長辺1600pxに縮小して data/sample-photos/<group>/ に保存）。現在の写真のサムネイルを表示。
- CLI（任意）: `node cli/sample-pages.js --ids-file ids.txt --label 兵庫_健康系_20261118` で作成し、CSVを出力。

## 公開URLについて

当面は `https://webdock.stoc-plus.site/s/12345`。将来 `stoc.jp/12345` に向けられるよう、ベースURLは環境変数 `SAMPLE_BASE_URL`（未設定なら webdock のURL）で変えられるようにする。

## 安全・その他

- 電話番号・住所などはすべてエスケープして出力。
- Googleマップの埋め込みは `https://www.google.com/maps?q=<住所>&output=embed`。
- 管理画面の操作は既存のログインとCSRFの仕組みに載せる。
- 自動削除は今回は作らない（一覧で「作成から30日・掲載OKでない」ものを絞り込めればよい）。
